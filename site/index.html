The problem

Deploys don't reach open tabs.

You shipped 1.5.0 at noon. Three people still have the app open from this morning, running yesterday's JavaScript against today's server.

Stale chunks. Lazy-loaded files from the old build are gone, so navigation breaks.

Changed APIs. Old code sends old requests, and the server refuses them.

Fixed bugs, reported again. Support chases bugs that a reload would fix.

Features

Every tab on the live version, without nagging anyone.

A small client in your app, a CLI in your CI, and a dashboard for the moments that need a person.

How it works

Running in five minutes.

  1. 1

    Run it

    Start the server and add your app. Each environment gets a public key and a deploy token.

    terminal 
    $ git clone https://github.com/openstuff-dev/open-version
$ cd open-version && docker compose up -d
  2. 2

    Add the client

    Tell it the version your build is. <ov-update> shows the toast.

    main.ts 
    import { configure } from '@openstuff-dev/version';
import '@openstuff-dev/version/update';

configure({
  url: 'https://version.example.com',
  publicKey: 'pk_…',
  version: import.meta.env.VITE_APP_VERSION,
});
  3. 3

    Publish from CI

    One step after your deploy. Open tabs hear about it at their next check.

    .github/workflows/deploy.yml 
    - run: npx openversion release --minor --notes-file CHANGELOG.md
  env:
    OPENVERSION_URL: https://version.example.com
    OPENVERSION_TOKEN: ${{ secrets.OPENVERSION_TOKEN }}

FAQ

Questions people ask first

Is it free?

Yes. OpenVersion is open source under the MIT licence, so self-hosting costs nothing but your server.

Will it reload a page while someone is typing?

Not for a normal release: people get a toast and reload when they choose. A hard release or a hard refresh waits until the tab is hidden or the person navigates, or shows a countdown with Reload now. Your app can also take over the forced reload, for example to save a form first.

Does it work with my framework?

Yes. The client is plain JavaScript and <ov-update> is a web component, so it works with Angular, React, Vue, Svelte or none. Give it the version your build is, from your bundler or package.json.

Where is my data?

On your own server, in your Postgres. OpenVersion keeps your apps, releases and a per-minute count of version checks for the last hour, with no addresses or user data. Admins can export everything to one JSON file.

How is this different from a service worker update?

A service worker knows a new build exists only after it downloads one, and it can't roll back or force a reload across every tab. OpenVersion knows what's live from your CI, works without a service worker, and gives you rollback and hard refresh. They work fine together.
